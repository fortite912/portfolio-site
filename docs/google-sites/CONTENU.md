## 0. Réglages du site (à faire en premier)

1. Aller sur <https://sites.google.com> → **Créer un site** → modèle *Vierge*.
2. **Nom du site** : `Portfolio BTS SIO SISR — Sean Fritsch`
3. **Thème** : `Impression` (le plus sobre) → palette **sombre** si disponible, police **Titre : Jost / Texte : Karla**.
4. **Partage** (indispensable pour que le prof voie la page) :
   - Bouton **Partager** en haut à droite
   - Section *Site publié* → **Modifier** → choisir **Public** ou **Toute personne disposant du lien**
   - Sinon le prof aura une page « Vous n'avez pas accès »
5. **Publier** → choisir une adresse du type `portfolio-sean-fritsch`

> ⚠️ Publier ≠ partager. Tant que le partage du *site publié* est sur « Restreint »,
> le lien ne marchera pas pour ton professeur. Vérifie-le en ouvrant le lien
> dans une fenêtre de navigation privée avant d'envoyer le mail.

### 2.4 Projet entrepreneurial — Soveris

```
Soveris — agent de tri des demandes de support informatique de niveau 1
Porté sous statut étudiant-entrepreneur (SNEE), Pépite Paris Ouest Nord, depuis septembre 2026

Un prototype qui lit une demande de support, décide si elle peut être résolue automatiquement et propose la réponse correspondante. Tout le traitement se fait en local, en Python et sans dépendance externe : les données ne sortent pas de la machine.

Résultats du banc de validation indépendant :
• 46 décisions correctes sur 50 cas, soit 92 % de précision
• 0 fausse résolution dangereuse
• 19 tests automatisés sur 19 au vert
• 70 % de résolution automatique sur le jeu de démonstration de 10 tickets
• Base de connaissances de 15 articles

Code public : https://github.com/fortite912/soveris

Ce que Soveris n'est pas :
• Un produit déployé en production — c'est un prototype
• Un outil entraîné sur des données réelles d'entreprise ou d'établissement : le banc de test est construit sur des cas fictifs
• Les limites connues sont documentées publiquement dans le fichier LIMITES.md du dépôt
```
